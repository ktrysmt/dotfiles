# 日本語の書き方

人が読む日本語の文章に適用します。対象は次のとおりです。

- チャットの返答
- Markdown の文書
- GitHub の PR と Issue の本文、コメント、レビューコメント
- Slack のメッセージとキャンバス

GitHub と Slack では、以下の規則にある「返答」を「投稿 1 件」と読み替えます。

## 文章の流れ
- 前の文に出た語か、一般に通じる語から文を始めます。新しい情報は文の後ろに置きます。
- 指示語は、指す内容のすぐ後で使います。離れる場合は名詞を繰り返します。

## 文の組み立て
- 一文が 50〜60 字を超えたら、分けられないかを考えます。
- 一文に入れる論点は 1 つにします。
- 接続助詞の「が」や連用形で文をつなげず、句点で切ります。
- 「いつ・どこで・誰が・何を・どうした」の順に書きます。
- 文の途中で主語を変えません。
- 係る語と受ける語を近くに置きます。修飾語が複数あるときは、長いものを先に書くか、文を分けます。
- 2 通りに読める文は書き直します。

## 語の選び方
- 読み手に通じる語を使います。定着していない一般の外来語は、漢語や和語に言い換えます。
- 製品や仕様が名前として定めた語は、原文の表記のまま書きます。
- 漢語を詰め込みません。
- 次のカタカナ語は、Claude Code の機能名と重なります: エージェント、スキル、タスク、フック、プラン、チーム、メモリ、ワークフロー、アーティファクト。これらの語を一般の意味で使うときは、漢語や和語に言い換えます。機能を指すときは、機能名をバッククォートで囲みます。
- 同じ助詞を続けて使いません。
- 受身形と二重否定は、必要なとき以外は使いません。
- 遠回しな言い方、比喩、ビジネス用語は使いません。次の語は右の語に言い換えます: 筋が良い→妥当 / 腹落ち→納得 / 肝→最も重要な点 / 勘所→注意点 / 地雷→不具合の原因 / 刺さる→効果がある / 詰む→先に進めなくなる / 寄せる→統一する / 倒す→(既定値を)〜にする / 握る→合意する / 温度感→優先度 / 解像度→詳しさ / 一次情報→元の資料 / ワークする→機能する
- 英語の名詞を直訳した語は使いません。次の語は右の語に言い換えます: 経路(比喩)→手段 / 表面に出す→示す / 着地→結論 / 所有者→担当者

## 文体
- です/ます 体で統一します。

## 送信前の確認
返答や投稿を送る前に、初見の読み手のつもりで読み返します。次の 6 点を確かめ、止まる箇所を直します。
1. 結論が最初の段落にあるか。返答全体が 100 行程度に収まっているか。
2. どの文にも主語と目的語があるか。前の返答を読まなくても、すべての語の指す対象が分かるか。
3. 60 字を超える文や、論点が 2 つある文がないか。
4. 前の文とのつながりが分かるか。新しい情報が文の頭に来ていないか。
5. 2 通りに読める文や、削っても意味が変わらない文がないか。構造の説明は図や表にしたほうが短くならないか。
6. 製品や仕様が名前として定めた語を、原文の表記のまま書いているか。
