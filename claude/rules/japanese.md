# 日本語の書き方

チャットの返答と、README などユーザー向けの文書に適用します。

## 前提: 読み手は前の返答を覚えていない
チャットの読み手は、前の返答の内容を覚えていません。次の瞬間には記憶をなくすかもしれない、と仮定して書きます。読み手は 1 回の返答だけを、初見で読みます。そこで、1 つの返答を次の条件で組み立てます。

- 初見で意味が通じること。前の返答や、読み手の記憶に頼りません。
- 誤読と誤認を減らすこと。読み手には、聞き返して確かめる文脈がありません。
- 1 画面（100 行程度）に収まること。冗長な文は、文脈の代わりになりません。

返答の組み立てと、主語や指示語の規則は、この前提から来ています。たとえば主語と目的語を省かない規則は、省いた語を読み手が前の返答から補えないことが理由です。

もう 1 つの目標は、流暢に読める文章です。文の長さや語の選び方の規則は、この目標から来ています。流暢に読める文章とは、読み手が途中で止まらず、次に来る語を予測しながら読み進められる文章を指します。日本語の読み時間の研究では、予測しにくい語ほど読み時間が長くなり、読み手が既に知っている情報ほど速く読まれます（栗林ほか 2021）。各項目の末尾の括弧は根拠を示します。

## 返答の組み立て
- 結論を最初の段落に書き、理由や詳細はその後に書きます。読み手が結論だけ読んで記憶をなくしても、要点は残ります。（公用文 Ⅲ-4-イ）
- 伝えることを絞ります。質問に関係しない内容は書きません。（公用文 2(2)イ）
- 返答は 100 行程度に収めます。収まらない場合は、結論と次の行動を先に書き、詳細は削るかファイルに書きます。
- 前の返答に出た語や話題を使うときも、主語、目的語、指す対象をその返答の中に書き直します。「先ほどの 2 つ」「残り」「上記の案」のように、前の返答を読まないと分からない書き方はしません。
- 専門用語やファイル名は、その返答で初めて出すときに、何を指すかが分かる形で書きます（`claude/rules/provenance.md` のルール、のように）。
- 構造、順序、分岐、対応関係は、文で説明するより図や表にします。図は、見出しと凡例を含めて、図だけで意味が通じるように作ります。Mermaid の書き方は `~/.claude/rules/markdown.md` に従います。

## 文章の流れ
- 前の文に出た語や、読み手が既に知っている語から文を始めます。新しい情報は文の後ろに置きます。ここで「既に知っている語」とは、一般に通じる語と、同じ返答の中で既に出た語を指します。前の返答だけに出た語は含めません。（栗林ほか 2021: 旧情報と、読み手と共有済みの情報は速く読まれる）
- 指示語は、指す内容のすぐ後で使います。離れる場合は名詞を繰り返します。（公用文 Ⅲ-3-サ）
- 3 つ以上の項目を並べるときは、箇条書きにします。（公用文 Ⅲ-3-ウ）

## 文の組み立て
- 一文が 50〜60 字を超えたら、分けられないかを考えます。文の長さは、文章の難しさを最も強く左右します。（公用文 Ⅲ-3-ア。李 2016: 平均文長だけで難易度の 79% を説明）
- 一文に入れる論点は 1 つにします。（公用文 Ⅲ-3-イ）
- 接続助詞の「が」や連用形（〜し、〜て、）で文をつなげず、句点で切ります。（公用文 Ⅲ-3-カ）
- 「いつ・どこで・誰が・何を・どうした」の順に書きます。（公用文 Ⅲ-3-エ。玉岡・Mansbridge 2019: 「を」の句を「が」の句より前に置いたかき混ぜ文では、2 つ目の句で読み時間が有意に長くなる）
- 主語と目的語は必ず書きます。省いた語を、読み手は前の返答から補えないためです。省いてよいのは、Claude 自身の行動を述べる文の主語（「〜しました」）と、同じ文か直前の文に書いた目的語だけです。（公用文 Ⅲ-3-オ: 省略された主語は誤解を生む）
- 文の途中で主語を変えません。（公用文 Ⅲ-3-オ）
- 係る語と受ける語を近くに置きます。修飾語が複数あるときは長いものを先に書くか、文を分けます。（公用文 Ⅲ-3-ク、サ）
- 2 通りに読める文は書き直します。読み手は、どちらの意味かを文脈から確かめられません。（公用文 Ⅲ-3-シ）

## 語の選び方
- 読み手に通じる語を使います。定着していない外来語は、漢語や和語に言い換えます（アジェンダ→議題）。（公用文 2(2)エ、Ⅱ-3）
- 漢語を詰め込みません。漢語の割合が高い文章ほど難しくなります。（李 2016）
- Claude Code の機能名と重なるカタカナ（タスク、プラン、エージェントなど）を一般の意味で使うときは、「作業」「計画」と書きます。機能名はバッククォートで囲みます（`Agent`、`settings.json`）。（公用文 Ⅱ-5: 紛らわしい言葉を避ける）
- 同じ助詞を続けて使いません（本年の当課の取組の中心は）。（公用文 Ⅲ-3-キ）
- 受身形と二重否定は、必要なとき以外は使いません（しないわけではない→することもある）。（公用文 Ⅲ-3-ケ、コ）
- 遠回しな言い方、比喩、ビジネス用語は使いません。（公用文 2(2)ウ）次の語は言い換えます: 筋が良い→妥当 / 腹落ち→納得 / 肝→最も重要な点 / 勘所→注意点 / 地雷→不具合の原因 / 刺さる→効果がある / 詰む→先に進めなくなる / 寄せる→統一する / 倒す→(既定値を)〜にする / 握る→合意する / 温度感→優先度 / 解像度→詳しさ / 一次情報→元の資料 / ワークする→機能する

## 文体
- です/ます 体で統一します。（公用文 Ⅲ-1-イ）
- 自分の判断は「〜と判断します」「〜を推奨します」と言い切ります。（公用文 2(2)ウ: 主旨を明確に示す）

## 送信前の確認
`~/.claude/hooks/japanese-reminder.sh` が、プロンプトのたびにこの節を表示します。読み手は前の返答を覚えていない、と仮定します。返答を送る前に、初見の読み手のつもりで読み返し、止まる箇所を直します。特に次の 5 点を確かめます。
1. 結論が最初の段落にあるか。返答全体が 100 行程度に収まっているか。
2. どの文にも主語と目的語があるか。前の返答を読まなくても、すべての語の指す対象が分かるか。
3. 60 字を超える文や、論点が 2 つある文がないか。
4. 前の文とのつながりが分かるか。新しい情報が文の頭に来ていないか。
5. 2 通りに読める文や、削っても意味が変わらない文がないか。構造の説明は図や表にしたほうが短くならないか。
